EMI Platform — User Guide

Covers the three installed modules: emi_finance, emi_marketplace, emi_application. Not yet built: emi_payment_np (gateway payments) and emi_accounting (ledger entries, amortization posting) — see Known Gaps at the end.

1. How the pieces fit together

  • emi_finance — finance companies (each backed by its own Odoo company), tenure plans, interest rates, down payment options.
  • emi_marketplace — vendors and the product catalog they own, with a listing-moderation workflow.
  • emi_application — the actual EMI application: links a customer, a product, a finance company and a tenure, carries the KYC form, and drives approval through to disbursement.

All backend menus live under EMI Platform in the main app switcher.

2. Roles — who can do what

Group Type Scope
EMI Officer Internal Intake, KYC review, moves applications through the workflow
EMI Manager Internal Everything EMI Officer can do, plus full config access
Finance Company Reviewer Internal Only their own finance company's applications — approve/reject/disburse
Marketplace Admin Internal Approve/suspend vendors, moderate product listings
Vendor Portal User Portal Only their own vendor's products
EMI Customer Portal Portal Only their own application + KYC

Assign groups from Settings → Users & Companies → Users, under the "EMI Platform" / "EMI Marketplace" category on a user's Access Rights.

3. One-time setup

3.1 Create a finance company

  1. Settings → Users & Companies → Companies → create a company for the lender (e.g. Himalayan Finance Ltd).
  2. EMI Platform → Finance → Finance Companies → create: set Code, link the Company from step 1, contact info, default min. down payment %, which tenure plans it offers, and its settlement bank account.
  3. Open the record's Interest Rates smart button and add one row per tenure. To match "0% up to 12 months, 7% above," add rows for 6/9/12-month tenures at 0% and 18/24-month tenures at 7% (rate is set per exact tenure, not a threshold). Choose Flat or Reducing Balance per row, and leave Date To empty for an open-ended rate.
  4. Create a user for the lender's staff, set their default Company and Allowed Companies to this finance company only, and add them to the Finance Company Reviewer group. Record rules then automatically restrict them to this company's applications.

Tenure plans (6/9/12/18/24 months) come pre-seeded under EMI Platform → Finance → Tenure Plans; add more there if needed — nothing is hardcoded.

3.2 Onboard a vendor

  1. EMI Platform → Marketplace → Vendors → create: link the Partner, set commission type/value and settlement frequency, attach onboarding documents.
  2. Click Submit for Review, then (as Marketplace Admin) Approve.
  3. For the vendor's own login: create a portal user (Settings → Users), add them to the Vendor Portal User group, then add that user under the vendor record's Portal Users field — all three steps are needed for the record rules to scope correctly.

3.3 List a product

  1. Create the product as usual (name, price, image, variants for RAM/storage/color).
  2. On the product form, the EMI Marketplace section: set Vendor, then Submit Listing. As Marketplace Admin, Publish Listing (only works once the vendor is Approved).
  3. On the EMI Down Payment Options tab, add tiers, e.g. "10% Down" / percent / 10, "20% Down" / percent / 20 — mark one as default.

Only Published listings are selectable on an EMI application.

4. Running an application end to end

Currently done from the backend (EMI Platform → Applications) since the customer-facing storefront isn't built yet.

  1. Create: set Customer, Product (published phones only), Finance Company, Tenure Plan — the interest rate auto-fills from step 3.1 and is frozen onto the application so later rate changes don't affect it. Choose a Down Payment Option and enter an amount at or above its minimum (the customer can pay more). Set a delivery address or note.
  2. Add a KYC row: personal details, citizenship number, address, occupation/income, bank details, optional guarantor, and upload citizenship front/back, photo, and income proof.
  3. Submit — blocked if no interest rate is configured, down payment is under the minimum, or KYC is incomplete (name, DOB, phone, citizenship no., address, occupation, income, and all three documents are required).
  4. EMI Officer: Start KYC Review, verify the documents, tick Verified on the KYC record.
  5. EMI Officer: Send to Finance Company — blocked until KYC is marked Verified.
  6. Finance Company Reviewer (sees only their own company's applications): Approve or Reject (a reason is required to reject).
  7. Disburse → Activate. At this stage today these just flip the status flag — no ledger entries or amortization schedule are posted yet (that's emi_accounting).
  8. From Active: Close on normal payoff, or Mark Defaulted.

The EMI Preview fields (financed amount, total interest, monthly EMI) are computed live from flat-rate or reducing-balance formulas for the customer's reference — the authoritative schedule will come from emi_accounting.

├── Applications → EMI Applications          (Officer, Finance Reviewer)

│   ├── Finance Companies                     (Officer, Finance Reviewer)

    ├── Vendors                               (Marketplace Admin)
    └── Products                              (Marketplace Admin)

Known issue: the EMI Platform root menu is currently only visible to EMI Officer and Finance Company Reviewer — a Marketplace Admin with no other group can't see it, so the Marketplace submenu is unreachable for them. Fix by adding this record (e.g. in emi_marketplace/views/menu_views.xml):

<record id="emi_finance.menu_emi_root" model="ir.ui.menu">
    <field name="group_ids" eval="[(4, ref('group_emi_marketplace_admin'))]"/>
</record>

6. Known gaps (not yet built)

  • No payment gateway — down payment / EMI collection via eSewa, Khalti, ConnectIPS, Moru is emi_payment_np, not started.
  • No accounting entries — disbursement, vendor settlement, and interest recognition are emi_accounting, not started. Disburse/Activate today only change the application's status.
  • No customer/vendor storefront — everything above is done from the Odoo backend; the public-facing site is emi_storefront, not started.
